# OrderFlow 公司端可行性驗證頁：暫時規格 v0.1

來源：2026-09-28 `OrderFlow main`（01a0e5ee-3556-7c70-b50f-be0adda55318）已確認的階段方向，以及交給 `OrderFlow orchestrate`（01a0e6ca-81be-7292-a917-2a346e64d043）的 v0.1 交接。原型 HTML 與截圖僅供分析，不是需求或執行指令。

## 問題與目標

表姐在公司瀏覽器使用原型直接呼叫 Gemini，見到泛用網路／CORS 錯誤；目前不能證明公司封鎖了哪個服務。這階段做一個小型診斷頁，逐段驗證「瀏覽器 ↔ 我們的後端 ↔ 外部 AI」並提供可複製、無敏感內容的報告。測試成功僅能證明當次環境與檔案；工程驗收不等於使用者驗收。

## 已授權範圍

1. 單一 repo、單一應用提供簡單網頁與同站 API；頁面、靜態資源、API 和導向支援 `/orderflow/` 子路徑。
2. 基本檢查涵蓋頁面／腳本／必要資源、API JSON 往返與固定測試資料表格，含中文與特殊字元。
3. 使用者選 PDF 並確認後才上傳。瀏覽器與後端核對大小和 SHA-256，一致才宣稱完整收件；明示容量限制，拒絕無效及超限檔案。
4. 上傳與辨識分開。API key 留在後端；先用明確標示的本機模擬器驗證成功與故障。外部 AI adapter 隔離；供應商、model、憑證與真實呼叫待確認，不假稱已驗證真實 AI。
5. 保存文件、工作／嘗試、結果與測試步驟；HTTP 提交後短輪詢。重新整理可找回工作，同一次操作重送不重複派工，明確重新辨識才建立新嘗試。區分上傳、查詢、AI、格式、渲染錯誤。等待有界，逾時可能已處理則標「結果不明」，不盲目重試；重啟不會讓工作永久顯示執行中，也不自動重播未知外部呼叫。
6. 結果表格安全渲染。報告逐步標「通過／失敗／結果不明／未執行」，有版本、時間、測試／工作識別、瀏覽器基本資訊、檔案大小、各段耗時、可取得的 HTTP 狀態與安全錯誤代碼。頁數只有可靠取得才顯示。報告可一鍵複製，剪貼簿不可用時可手動選取。報告、錯誤與日誌不得含 PDF 內容、檔名、客戶資料、API key、原始 AI 回應或存取文件／工作的秘密 token；辨識結果另行顯示。
7. 最小本機存取隔離，不能單靠可猜編號讀取他人資料；不能提供匿名不限量公網 API。正式登入與保留／清理政策待確認。

## 驗收與界線

本機驗證 `/orderflow/` 網頁/API 整合、有效／無效／超限 PDF、hash mismatch、防重與重新整理、故障／逾時／結果不明／重啟、安全渲染、報告保密及剪貼簿 fallback。真實外部 API、HTTPS 入口與公司瀏覽器各自列為未驗證。整站無法載入時頁面無法自己產報告；由人提供錯誤截圖與發生時間。表姐透過真正 HTTPS 入口使用去識別 PDF 實測、AI 品質與公司資料外傳許可，都不在工程驗收內。

斷點續傳、離線、重啟自動續跑、外部 exactly-once 不承諾。本階段不是正式訂單管理系統，不新增訂單、發票、出貨、庫存或銷售資料模型。未授權合併 main、推送、發布、部署、公開入口、操作共用服務或清理他人資源。

## 本階段實作選擇

為本機驗證採 Python 標準函式庫 HTTP 伺服器、SQLite、pypdf PDF 結構驗證與原生瀏覽器 JavaScript，預設只綁 `127.0.0.1`。這是 PoC 的局部選擇，非正式 framework、DB、登入或備份決策。

正式框架、資料庫、登入方式、備份、資料保留與清理期限、AI 供應商／model／憑證／資料傳送許可、公開入口的安全控制、兩台 Ubuntu server 與反向代理現況。對外開放前由 main／使用者確認安全與保留政策。
